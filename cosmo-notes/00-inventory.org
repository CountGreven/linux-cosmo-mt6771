* Mainlining the Cosmo Communicator (MT6771) — what we know

Goal: a modern, maintained kernel on the Planet Computers Cosmo Communicator, primarily for security.
Upstream acceptance is welcome but not the driver of decisions.

** Starting position (checked 2026-09-24)

| Thing | State |
|---|---|
| Vendor tree | =cosmo-linux-kernel-4.4=, Linux *4.4.146*, fork of gemian, board =k71v1_64_bsp= |
| Mainline | *v7.3-rc4*. *No MT6771 support at all* — no dtsi, no compatibles, nothing |
| Prior art | [[https://github.com/affenull2345/linux][affenull2345/linux branch =mt6771=]] — Otto Pflüger, 2023, "Add MT6771 and Planet Cosmo Communicator". Reference only, not a base |
| SoC | MT6771 (Helio P60/P70): 4× Cortex-A73 + 4× Cortex-A53, GIC-v3 |
| Board DTS | A device-tree *overlay* (=/plugin/=) on =mt6771.dts=; 1063 lines, thin |
| SoC DTS | =mt6771.dts=, 4358 lines, 455 addressed nodes, 507 =mediatek,*= compatibles — this is the spec |

** The key finding: MT6771 ≈ MT8183

MT8183 (same generation, well supported in mainline) shares **90 of its 101 addressed blocks with MT6771 at
the identical base address** — topckgen, infracfg, pericfg, pinctrl, pwrap, watchdog, systimer, iommu, gce,
scp, auxadc, uart, i2c, spi, pwm, thermal…

So the work is mostly *not* writing drivers. It is:

1. Write =mt6771.dtsi= modeled on =mt8183.dtsi=, with values taken from the vendor =mt6771.dts=.
2. Add MT6771 entries (compatible + per-SoC data tables) to drivers that already exist upstream:
   clocks, pinctrl, i2c, spi, mmc…
3. Write =mt6771-planet-cosmo.dts= for the board.
4. Only then, the genuinely device-specific work: panel, touch, wifi, audio, charging.

Already mainline-supported compatibles used by this SoC: =mediatek,mt6577-uart= (the console!),
=mediatek,mt6577-sysirq=. Not yet: =mediatek,mt6771-i2c=, =mediatek,mt6771-spi= — but the drivers exist and
take per-SoC data, so these are table entries, not new drivers.

** Board hardware (from the vendor overlay)

Charger =rt9465= · PMIC/backlight/LED =mt6370= · GPIO expander =mt6306= · ALS/proximity =stk3x1x= ·
accel+gyro · fingerprint (=cs_finger=) · vibrator · backlights for LCD, keyboard, jogball, buttons.

** Boot and test loop (no UART yet)

- *Flashing is required.* No =fastboot boot= on MediaTek LK; arm64 kexec did not exist in 4.4
  (landed upstream in 4.8) and MediaTek did not backport it — =arch/arm64/Kconfig= has zero KEXEC references.
- *Safety net:* Planet's dual-boot firmware provides spare boot partitions plus a boot menu, so a failed
  experiment is a menu choice away from a working system. mtkclient (kamakiri, MT6771) reaches BROM if all
  boot partitions are dead — *prove this works before it is needed*.
- *Console without a cable:* =pstore=/=ramoops= (read the previous boot's log from a working system) and
  =simple-framebuffer= (LK leaves the panel initialised).

** Milestones

0. Prove the loop: build the vendor kernel ourselves, flash a spare slot, boot it, read pstore.
1. Sign of life: minimal =mt6771.dtsi= (GIC, timer, UART, essential clocks) booting to a console.
2. Storage (MSDC) and USB → a shell over USB networking.
3. Display and touch.
4. Wifi, audio, charging, sensors.
5. Modem and camera — possibly never; not required for a usable machine.

** Environment

- Trees under =/storage/kernel/= (root filesystem is nearly full; =/storage= has ~660 GB).
  =cosmo-linux-kernel-4.4= (vendor), =mainline=, =mt6771-ref= (Otto's, reference), =cosmo-mainline= (ours).
- Cross toolchain: =aarch64-linux-gnu-gcc= 13.3, =dtc= 1.7, ccache.
