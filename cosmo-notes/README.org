* How these notes work

Org, not markdown, so an open question is a =TODO= that can be listed, agenda'd and closed rather than a
bullet someone has to re-read. Every task writes one file, =NN-topic.org=, and the work's history lives
here — which is also what a blog post gets written from later.

** Rules for anything writing here

1. *Open questions are =TODO= headings*, never prose. If it is unresolved, it is a TODO with enough
   context to act on months later.
2. *Claims about hardware are =WAITING=* until something on the device proves them. "Compiles" is not
   "works"; say which one you mean.
3. *=VERIFIED=* is reserved for things checked against the hardware or a boot log — never for "the build
   passed".
4. *Cite the vendor tree* as =V:<line>= where V is
   =cosmo-linux-kernel-4.4/arch/arm64/boot/dts/mediatek/mt6771.dts=, or give the full path for other files.
5. *Invented values are marked =STAND-IN=* in both the code and the notes, with what they should become.
6. *Tag entries worth publishing* with =:blog:=. A post is assembled from those, so write the interesting
   ones as if a stranger were reading: what was tried, what surprised you, what it cost.
